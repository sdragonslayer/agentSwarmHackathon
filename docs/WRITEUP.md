# SwarmScope: write-up

**Trace the handoff. Inspect the evidence.** Hackathon submission: AI Village × Grove Research Swarm Dynamics, Oct 3-4, 2026.

## What I built and how to use it

Studying how agents in a swarm pass things to each other (a workaround, a link, an answer) has a counting trap:
agents keep rewriting the same text. An AI Village agent rewrites its long memory note over and over (one label has 34,491 memories), and a wiki
revision repeats the whole page with one line changed. If every rewrite is counted as a new utterance, a string written
once looks like it spread hundreds of times, and a label that merely *saved* a revision looks like it *wrote* the text
in it. SwarmScope is an offline tool that removes that distortion and then lets a researcher inspect the evidence for any
one artifact.

**How it works.** Each source is loaded into a DuckDB file without altering any source value (text, times, ids). Every
author label stays separate, and a blank label is "unknown", never one shared agent. Per-label memory streams and per-page
revision chains are split line by line into *carried forward*, *new*, *edited*, *restored* (reappears after removal; not new
authorship) and *first seen* (earlier history missing from the release). Exact URLs, commit-like ids and `owner/repo#N`
refs are extracted from the text and counted twice: in all text, and in new text only. The gap is "occurrence inflation".
Artifacts shared by different labels get undirected `same_content` links, each stored with its evidence tier, how strong
its ordering is, and the competing explanations (common source, shared prompt, independent discovery, carried memory).
Each case gets a report whose answers cite exact source spans (what labels are doing with it, which topics, how fast it reached
other labels, who explicitly pointed back at earlier material) and abstain ("unknown") where the data cannot
answer. Similarity and shared strings are never presented as causation.

**How to use it.** `uv sync`, then build a dataset into its own database (the wiki takes about 15 seconds; AI Village
about 2.5 hours), run `validate`, and open the app: `uv run uvicorn backend.app.main:app` (set `SWARMSCOPE_DB` to pick the
dataset). In the browser: search for a URL, commit id or phrase, or pick a case; read the timeline (one lane per author
label; hover a dot to light up its links; **Conservative mode** keeps only links whose order the source's own sequence
establishes) or the graph; click a dot to see the text with every line tagged carried/new/edited/restored; click a link to
see its evidence and record an accept/reject/uncertain review; export the case as Markdown or JSON. A static results page,
CSV tables and a 133-item human-review pack are generated by `report`, `export_results` and `review_pack`. Full commands:
`docs/USAGE.md`.

## What it is for
- **Audit a spread claim.** Before saying "this workaround spread to N agents", see how many of those are carried-forward or
  restored copies, who actually wrote it, and which of the links are exact strings versus guesses.
- **Find the explicit coordination in a swarm record.** The tool surfaces named requests and replies between labels, pages that
  point at other labels' pages, and the topics where answer, relay and bypass language concentrates, each with the text behind it.
- **Hand someone evidence they can check.** Every statement has an exact source span, a stated limit and the competing
  explanations; a case exports as Markdown or JSON.
- **Say "we cannot tell".** It reports where recorded text cannot separate two readings (for example independent work on the
  same task versus relaying), instead of drawing a graph that implies one.

## What it found

All numbers count text occurrences in the loaded releases. Labels are not verified agents.

1. **Carryover dominates the text.** On AI Village, 78.7% of 73.1M memory lines are carried forward unchanged from the
   same label's previous memory. On the German message board, 43.2% of 185,849 revision lines are carried forward and a
   further 25.1% are restorations. One wiki page (`WillkommenImWiki`, 2,327 revisions) accounts for 89.8% of the restored
   lines.
2. **Naive occurrence counts overstate repetition a lot.** URLs appear 4.35M times in AI Village full text but 655k times
   in new text (6.6×); on the wiki 115,837 vs 42,916 (2.7×). Commit-like ids: 4.2× and 6.6×.
3. **Whether carryover also inflates *who shared what* depends on the source.** On AI Village, memories are per-label, so
   carryover never crosses labels and label-level sharing is unchanged (14,128 URLs in 2+ labels either way). On the
   wiki, saving a revision inherits other labels' text, so naive counting makes **2.4× as many URLs look shared across
   labels** (8,292 vs 3,485 when only text a label wrote counts; commit-like ids 3.6×, 316 vs 88). Example: a
   `proxymule.com` proxy URL for fetching a `sec.gov` file sits in the revisions of **26** labels, but only **8** wrote it.
4. **Coordination traces by topic (German message board; `docs/EXPERIMENTS.md`).** Using the publisher's own page families as
   topics and a word list built from the real vocabulary, answer-sharing language is in 38.9% of revisions in task topics versus 3.1%
   in infrastructure pages, and ask-to-relay language 50.9% versus 3.7%. Labels name each other and link each other's pages
   (5,939 resolved references; 63.5% of page references point at pages the writer never wrote on) and 34 request-and-reply exchanges
   are recorded, median reply 13 minutes. 170 numbers written on answer lines appear in 2 or more labels (44 in 10 or more); but
   only 9.9% of later repetitions of such a number also name an earlier writer, so most of the overlap cannot be classified as
   relaying versus independent work on the same data. And 75% of all labels first appear in a single week, so apparent adoption
   curves mostly show an arrival wave, not spread: the tool plots arrivals next to usage.
5. **Concrete cases the tool surfaces.** Wiki: lists of proxy and mirror URLs for fetching
   `https://www.sec.gov/files/county.json` written by 8 labels, with one label posting the same list on 15 different pages
   (item counts overstate independent writing; label counts are safer). AI Village: one agent announces a pull request in
   chat, another agent's memory logs it about 35 seconds later, and the first replies "I already opened PR #3"; and a
   shared document link that one agent flags as a typo and records as such in its memory. The tool shows the strings, labels
   and recorded order, and lists the alternatives, but it does not claim one agent learned from another.

## How I checked it

- 80 offline tests on synthetic data, including cases built to fail (corrupted hashes, lying hunks, tampered text, hostile
  strings in the corpus).
- 16 integrity gates on the wiki and 10 on AI Village, all passing: one record per source action, namespaced and unmerged
  labels, verbatim times with no invented bounds, lineage counts that add up, explicit bases being the immediate
  predecessor, source hashes round-tripping, edges never within one label or directed, every citation resolving to the
  exact source span, and an independent SQL recomputation of the inherited counts (0 mismatches in 200 samples per dataset).
- Source conventions were verified against the real wiki files before building on them: `body_sha256` matches for all 14,591
  revisions once the body is treated as bytes in its documented encoding (a UTF-8 hash fails for 251); hunks are 0-based,
  half-open over newline-split lines (10,012 of 10,012 consistent); `diff_base` is always the immediate predecessor; counts
  reconcile with the publisher's manifest. The same code ran on both datasets with only an adapter and fixtures added.
- Precision of the extracted artifacts and links has **not** been measured yet. A 133-item review pack is ready (links,
  extractions, lineage lines and answers, answers hidden from reviewers); results go here when scored: _not yet measured_.

## Limitations

- Shared strings are not proof of transmission: agents may read the same page or share a prompt. Order uses recorded
  database time, whose uncertainty neither source documents, so most links carry no established order (none on the wiki,
  3% on AI Village). Items and cases shown are chosen for being inspectable, not representative.
- Cue words are a hand-built list (precision not measured); topics are the publisher's heuristic page classification; the
  collusion.wiki site itself could not be consulted. Cues, references and exchanges show recorded text, not intent or reading.
- Only exact artifacts are linked; similar-wording retrieval exists but was slow and found few candidates on the full
  corpus, so it is not in the interface. There is no claim detection and no evidence that a use succeeded
  (`computer_use_turns` is not loaded).
- AI Village is one release and the wiki is its published cut (revisions from 2026-05-01); earlier history is missing for
  17 pages. Item counts in the wiki partly reflect automated, repetitive posting.
- The UI is a dependency-free page, not the planned React app.
